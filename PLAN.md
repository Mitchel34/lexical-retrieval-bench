# Lexical Retrieval Bench — frozen protocol candidate v1

This document fixes the protocol before implementation or observation of benchmark results. Acceptance is correct, complete, deterministic computation; there is no ranker-wins threshold. Everything is original synthetic material. This project measures lexical ranking, not semantic understanding or real-corpus quality. No model, API, third-party dependency, license grant or CI workflow is included.

## Components and execution boundary

Python package `lexical_retrieval_bench`: `core.py` contains the shared pure tokenizer, scoring, metrics, synthetic generator and self-contained `evaluate()`. It imports only `math`. CLI parsing and receipt export live in separate modules. The evaluator never imports those modules and never runs on import. A small `demo.py` uses three hand-written documents, one query and the same core. `demo/index.html` is a self-contained, static illustrated demo with a fixed three-document example and no JavaScript ranker, external assets or network request. A dependency-free wheel builder using existing Python stdlib will support one separately admitted clean offline installation; it does not invoke a package index. Tests use unittest and tiny hand-built cases only.

The inspected evaluation contract admits a single UTF-8 source at most 128 KiB, no filesystem/network/local imports, no private attributes or dynamic execution, and no names starting with double underscores. `evaluate()` returns only `checks` and `metrics`; at most 100 each, combined output at most 64 KiB. Metric keys match `[a-z][a-z0-9_]{0,47}`; check names match `[A-Za-z0-9 _().:-]{1,120}`. This project targets 90 metrics and 12 checks. No runner modifications, direct evaluation call, full batch unit test or exporter reranking is allowed.

## Normalization and scoring

Text must be a Python string without surrogate code points. Tokens are maximal runs of ASCII letters A–Z/a–z or digits 0–9. ASCII uppercase is lowered; every other character (including non-ASCII letters) is a separator. No Unicode normalization, stemming, stop-word removal, alias expansion or locale behavior. Empty text/token sequence is valid. Token occurrence order is preserved by tokenization; scoring terms are sorted lexicographically for stable accumulation. All rankers deduplicate query terms: repetition changes no query weight.

Let N be corpus document count, tf(t,d) raw occurrence count, df(t) the number of documents containing t, len(d) token count and avglen the mean token count. Query terms absent from the corpus contribute nothing and do not enter cosine normalization.

* `overlap`: score is the count of distinct shared tokens. Each shared token contributes 1.
* `tfidf`: smoothed idf(t) = 1 + ln((N+1)/(df(t)+1)). Document weight is tf(t,d)*idf(t). Query weight is idf(t) for each distinct in-vocabulary query token. Normalize each vector by its Euclidean norm. Score is the sum of shared-token normalized products. A zero document or query norm gives score 0 and no nonzero contributions. Do not round or clamp computed scores.
* `bm25`: explicitly the nonnegative ln(N/df) BM25 variant, k1=1.2, b=0.75, binary query weighting. Each shared token contributes ln(N/df(t)) * tf(t,d)*(k1+1)/(tf(t,d)+k1*(1-b+b*len(d)/avglen)). If avglen=0 all scores are 0. Ubiquitous terms have zero contribution. No query saturation factor or additive delta.

Every document participates, including zero scores. Sort descending full-precision score, then ascending ASCII document ID. Return first min(k,N). Never rely on insertion order to resolve ties. Explanations list all shared terms in ascending lexical order with actual per-term score contribution, including a zero BM25 contribution; the same contribution list is summed to obtain the score. Zero-norm cosine explanations use shared terms with 0 contribution. Scores/contributions must be finite and nonnegative; calculations use ordinary Python binary64 without rounding until presentation.

## Strict API and JSON CLI

CLI: `python -m lexical_retrieval_bench`, one JSON object on stdin, one bounded JSON object on stdout. Accepted top-level keys are exactly `version`, `documents`, `queries`, `qrels`, `ranker`, `k`; version must be integer 1, ranker one of the three names, k an integer 1–10. Booleans never satisfy integer checks. Documents and queries are arrays of exact `{ "id": string, "text": string }` objects. Qrels is an array of exact `{ "query_id": string, "grades": [{ "document_id": string, "grade": integer }] }` objects. Grade is 0, 1 or 2. Require exactly one qrels entry for each query, no others. Grade lists may be empty; omitted documents have grade 0. Reject repeated document IDs, query IDs, qrels query IDs and grade document IDs, and any unknown query/document reference. Document and query ID namespaces are separate.

Limits: 262144 input bytes, UTF-8 only without BOM; maximum nesting depth 8 counting each opened object/array, checked before decoding into containers. Documents 1–64; queries 1–36; grade entries 0–64 per query. IDs 1–32 ASCII characters from letters/digits/underscore/hyphen. Document text at most 2048 characters and 256 tokens; query text at most 256 characters and 32 tokens. Sum of all document/query text lengths at most 65536 characters. All decoded strings reject surrogate code points. Token count uses the frozen tokenizer. Empty corpus or query list rejected; empty document/query text allowed. Reject unknown fields, duplicate JSON keys at every level, invalid types, malformed JSON, trailing data, nonfinite literals, finite-overflow numeric forms and integer lexemes longer than 16 digits before conversion. There are no floating-point input fields, so even otherwise finite floats are rejected by schema. Schema checks occur before scoring. Public core entry points apply equivalent data/ID/k validation to direct calls; the evaluator uses bounded generated data through those same functions.

Success output has exactly `version`, `ranker`, `results`; results follow query input order. Each contains `query_id`, `ranking` (objects `document_id`, `score`, `matched_terms`; terms are objects `term`, `contribution`) and `metrics` with `recall_at_5`, `mrr_at_10`, `ndcg_at_10`. Metrics always use the complete ranking truncated to 10, independently of requested display k; each query is ranked once with top10 and display is sliced. Output serialization is bounded to 2 MiB; overflow is a stable error before writing. No partial success output. Errors have exactly `{ "error": { "code": CODE } }`, exit status 2, no input echo, traceback or private paths. Frozen codes: `invalid_json`, `invalid_utf8`, `input_limit`, `depth_limit`, `invalid_schema`, `output_limit`. Valid results exit 0. Error selection follows byte bound, UTF-8, lexical depth, JSON syntax, schema, output bound. For multiple schema defects no finer ordering guarantee is promised.

## Metric conventions and independent oracles

Positive means grade>0. Recall@5 = number of positives in first 5 / count of positives in full qrels; no positives gives 0. MRR@10 = reciprocal of first positive position in first 10, else 0. DCG@10 = sum (2**grade-1)/log2(position+1) through 10. IDCG uses descending grades over complete qrels, including relevant items absent from returned rankings, through 10; zero IDCG gives nDCG=0. Unknown ranking IDs or duplicate ranking IDs are rejected; unjudged known documents are grade 0. Partial rankings can be scored, with absent relevant documents contributing zero to DCG. API grades are validated even if outside the cutoff. Metrics must be finite; tolerance for checking their [0,1] bounds is 1e-12, without clipping values.

Hand-built oracle tests will use literal expected expressions/constants, not the metric implementation or synthetic generator: qrels a=2,b=1,c=1, others=0 and ranking [x,b,a,c] gives Recall@5=1, MRR@10=1/2, DCG=1/log2(3)+3/2+1/log2(5), IDCG=3+1/log2(3)+1/2. Ranking [x,b] gives recall 1/3, MRR 1/2, DCG=1/log2(3) with the same complete-qrels IDCG. Rank-6 positive misses recall cutoff, rank-10 positive has MRR 1/10, rank-11 misses MRR/DCG. Empty and all-zero qrels give all zero. An independent reviewer must verify these expressions before tests are accepted.

Scoring oracles: corpus a='amber amber', b='blue', c='' and query 'amber amber absent' gives overlap a=1,b=c=0; cosine a=1,b=c=0 (OOV ignored and repeated terms deduplicated); BM25 a=ln(3)*4.4/(2+1.2*(0.25+0.75*2/1)), with b=c=0. Corpus a='amber blue', b='amber', query 'blue' gives cosine a=I/sqrt(1+I**2), I=1+ln(3/2); b=0. Query 'amber' across corpus a='amber', b='amber amber' gives BM25 all zero and stable ID ties. Opposite insertion order, disjoint queries, token separators/non-ASCII, top-k>N and all-empty corpus document texts are separately tested.

## Frozen synthetic recipe

Seeds, in order: 7,23,101. Topics t=0..11 have (primary, signature, query-only alias) triples in this exact order:

`(velora, velsig, velalias), (nimbrel, nimsig, nimalias), (tavrik, tavsig, tavalias), (orsune, orssig, orsalias), (pelvix, pelsig, pelalias), (zandrel, zansig, zanalias), (quorlen, quosig, quoalias), (ivmora, ivmsig, ivmalias), (drelune, dresig, drealias), (fensora, fensig, fenalias), (ulveth, ulvsig, ulvalias), (karsumi, karsig, karalias)`.

Facets f=0..3 have tokens `faca, facb, facc, facd`, aliases `aliasa, aliasb, aliasc, aliasd`. Neutral tokens are `mote, reed, glint, spool, cairn, wisp, loom, pebble` in that order. Generic tokens are `archive, note`. These lists are disjoint; no aliases occur in documents.

For each seed s and each t,f in ascending nested order, latent index i=4*t+f, document ID is `d` followed by three decimal digits for ((17*i+s) mod48). This is a permutation of d000..d047 for every seed and disperses topic/facet position across the tie order. Emit corpus sorted by document ID. Target length L=16+((s+3*t+5*f) mod9). Construct token sequence in this order: primary[t] repeated 3+((s+t+f) mod3) times; facet[f] twice; signature[t] once; archive,note once each; primary[(t+1+(s mod11)) mod12] repeated ((s+t+2*f) mod3) times; then neutral[(s+t+f+j) mod8] for j=0.. until length exactly L. Join with single ASCII spaces. No PRNG or ranker-dependent generation.

Each topic's intended facet h=(s+t) mod4 comes from latent truth. Same-topic facet h has grade2; same-topic facets (h+1) mod4 and (h+2) mod4 have grade1; facet (h+3) mod4 and every other topic have grade0. This truth is generated directly from latent t,f and ID mapping, never text similarity or ranking scores.

Query ordering is topic ascending, then exact,noisy,mismatch. Query ID is `q` plus two decimal digits for t plus `_` and the stratum name. Exact query: primary[t], facet[h]. Noisy query: primary[t], facet[h], primary[(t+1) mod12], primary[(t+5) mod12], primary[(t+5) mod12], `staticnoise`. Mismatch query: alias[t], facet-alias[h]. Join with single spaces. The repeated contaminant is deliberately deduplicated by all rankers. The three variants share the same qrels. Each seed has 48 documents,36 queries,12 per stratum; every query has one grade2/two grade1 documents. All mismatch scores are zero; tie hits are chance retrieval and remain reported.

## Evaluation metrics, checks and exact work

For each seed in declared order, ranker in `overlap,tfidf,bm25`, query in declared order: rank top10 once, record ranking with unrounded scores and explanations, then metric triple. One complete repeat of the same traversal follows inside the same evaluation. Exactly 324 first and 324 repeat ranking calls; no third ranking for checking. Compare complete recorded objects by exact equality. Generate each seed dataset once and reuse it for repeat; check regeneration equality without ranking. All 108 query variants contribute equally within their strata.

The 81 quality keys are precisely the Cartesian product `s{seed}_{ranker}_{stratum}_{metric}` with seed in `7,23,101`, ranker in `overlap,tfidf,bm25`, stratum in `exact,noisy,mismatch`, metric in `recall5,mrr10,ndcg10`. Each is arithmetic mean over exactly12 first-pass queries. The nine accounting keys and exact values are `seed_count=3`, `documents_per_seed=48`, `total_documents=144`, `queries_per_seed=36`, `total_queries=108`, `ranker_count=3`, `first_pass_rankings=324`, `repeat_rankings=324`, `total_rankings=648`. Counts are derived from actual generated containers and incremented calls, with required exact equality checked; never substitute intended counts for measured counters.

Exactly12 check names/predicates: `dataset_counts` (all declared corpus/query/stratum sizes); `unique_ids` (document/query uniqueness per seed); `latent_qrels` (every query has one2/two1, known IDs, expected latent assignments); `paired_qrels` (three variants per topic have equal truth); `generation_repeat` (regenerated datasets exactly equal originals); `ranking_counts` (actual first/repeat counters 324 each); `ranking_order` (all returned rows sorted by score then ID, unique/known IDs, length10); `finite_scores` (all scores/contributions finite/nonnegative); `explanation_sums` (every score equals sum of its stored contributions); `repeat_equal` (every repeated ranking object equals corresponding first); `metric_bounds` (every per-query and reported quality value finite in [0,1] with1e-12 tolerance); `contract_keys` (exact90 keys, accounting values equal required counts and exactly12 checks). No performance threshold or preferred ranker assertion.

The production runner alone executes this workload after plan, implementation and ordinary-test gates, exact operation review/claim and fresh common-host admission. Initial evaluation caps:60 aggregate CPU seconds,256MiB operational memory,120wall seconds, one compute thread plus supervisor. Retain measured pre-closeout resources separately from conservative charged CPU. No retry of uncertain launch or evaluation tuning. Passing computation does not require any particular retrieval quality.
